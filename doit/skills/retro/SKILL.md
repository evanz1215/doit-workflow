# doit：手動檢討

參數：$ARGUMENTS

所有回報一律繁體中文（程式碼、指令、識別字除外）。

## 硬規則

- **不改專案檔案**：不用 Edit、Write 改程式碼，也不用 Bash 改檔。
- **不動任務**：不執行 `log.js --new`、`--set`、`--close`，不改任務檔與 `.doit/ACTIVE`。
- **教訓檔先問再寫**：分析完只提出建議，使用者同意後才用 `log.js --lesson`／`--lesson-bump` 寫入。使用者只同意部分時只寫那幾條。
- Bash 一次呼叫只跑一條指令，不用 `;`、`&&`、`||` 串接，不用 `$?`、`$(...)`。

## 分派

| 參數 | 做什麼 |
|---|---|
| 空白 | 跨任務，最近 10 個任務 |
| 數字 N | 跨任務，最近 N 個任務 |
| 任務檔路徑或檔名 | 單一任務：讀 `${CLAUDE_PLUGIN_ROOT}/skills/go/references/retro.md`（Read 被擋就用 `log.js --ref retro`），對這個任務照它的「怎麼做」走一次，寫入前同樣先問使用者 |

## 跨任務檢討

1. **收集任務**：列出 `.doit/tasks/` 與 `.doit/archive/`（含子目錄）下的任務檔，依檔名開頭的日期取最近 N 個。少於 3 個時告訴使用者樣本太少、看不出模式，改建議用單一任務模式，結束。
2. **讀資料**：
   - 每個任務的 `[錯誤 …]`、`[審查 …] 結論`、`[升級]`、`[範圍外]` 紀錄行，以及頂端的等級與類型。用 Grep 搜 `.doit/tasks` 與 `.doit/archive`，不用整份讀。
   - 耗時：`node "${CLAUDE_PLUGIN_ROOT}/tools/log.js" --timing --all`。
   - 既有教訓：`node "${CLAUDE_PLUGIN_ROOT}/tools/log.js" --lessons`。
3. **找模式**，每一類都要有至少兩個任務的證據才算模式，只出現一次的不提：
   - **重複的錯誤**：不同任務的 `[錯誤]` 是同一個根本原因（看原因，不是看字面）。已有對應教訓的歸到下一類；沒有的提一條新教訓。
   - **沒生效的教訓**：教訓的「犯錯次數」≥ 2，或這批任務裡又出現它描述的錯。代表規則寫得不夠具體、或放的階段不對，提出改寫後的預防規則。
   - **一直最慢的階段**：`--timing --all` 的「各階段由多到少」裡 agent 時間佔比最高的階段，回到各任務的紀錄看慢在哪裡（例如審查輪數多、某類步驟反覆修）。只有找得到具體原因時才提建議，找不到就只報數字。
   - **審查反覆**：同一個任務的 reviewer 或 plan-critic 跑 3 輪以上，看是哪一類意見讓它重跑，是否在多個任務重複。
   - **常見範圍外**：同一類 `[範圍外]` 在多個任務出現，代表可能是該獨立成一個任務的工作。
4. **提建議**：每條建議歸成一種：
   - **新教訓**：附完整條目（格式照 `retro.md`「教訓格式」），註明放全域（工具與環境的坑，`G-`）還是專案（這個 codebase 的坑，`P-`）。
   - **教訓加次數**：附編號與要加的是犯錯次數還是遇到次數（`--hit`）。
   - **改寫教訓**：附編號與新的「預防規則」。`log.js` 沒有改寫指令，改寫是用 `--lesson` 新增一條取代它的條目，並在新條目的「發生情境」註明取代哪一條；告訴使用者舊條目要不要刪由他決定。
   - **流程調整**：問題出在 doit 工作流本身（某個關卡太重、某條規則一直被誤解）時，寫成給 doit plugin 的建議，不寫進教訓檔。
5. **回報**，然後停下等使用者決定。

## 回報格式

直接輸出 Markdown：

```markdown
### 🔁 doit:retro：{一句話結論}

檢討範圍：{N} 個任務（{最早日期} ～ {最近日期}）；agent 時間 {總計}，最久的階段 {階段 佔比}

| # | 類型 | 發現 | 證據 | 建議 |
|---|---|---|---|---|
| 1 | 重複的錯誤 | … | `{任務檔名}`、`{任務檔名}` 的 [錯誤] 行 | 新教訓 G-00x（全域） |

- **沒有模式的**：{只出現一次、所以沒提的錯誤條數；沒有寫「無」}
- **要寫進教訓檔嗎**：回覆要採用的編號（例如「1、3」或「全部」）
```

沒有任何模式時，表格換成一句「最近 {N} 個任務沒有重複出現的問題」，附耗時摘要，結束。

## 使用者回覆之後

- 只寫使用者同意的編號。新教訓用 `log.js --lesson global|project` 搭配 heredoc（寫法見 `retro.md`「怎麼寫入」）；加次數用 `--lesson-bump`。
- 流程調整不寫任何檔案，回報裡已經寫清楚就好。
- 寫完列出寫了哪幾條（編號與檔案），結束。
