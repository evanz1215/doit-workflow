# 檢討與教訓檔

## 何時做

- 中風險與高風險：每次任務完成或中止後。
- 低風險：任務檔有任何 `[錯誤]` 行時。

## 怎麼做

1. 列出任務檔所有 `[錯誤 來源：… 分類：…]` 行。
2. 每一條問：**下次怎麼在發生前就擋住？** 答案寫成一條可執行的規則，不是「要小心」。
3. 判斷放哪裡：
   - **工具與環境的坑**（shell、Node、Windows 路徑、某套件版本行為、Claude Code 工具限制）→ 全域 `~/.doit/LESSONS.md`，編號 `G-`。
   - **這個 codebase 的坑**（某模組的隱含約定、某測試的副作用、某設定檔的陷阱）→ 專案 `.doit/LESSONS.md`，編號 `P-`。
4. 先搜教訓檔有沒有同樣的坑。有就只改「次數」與「最近」日期，不重複建條。
5. `來源：使用者 分類：需求` 的錯誤（使用者改了計畫）通常不是教訓，除非同類需求誤解重複出現。
6. 任務檔沒有 `[錯誤]`，但過程中有明顯的工具或環境坑（同一類指令被擋或失敗兩次以上、某個環境限制讓你繞了路），也寫一條全域教訓，「犯錯次數」填 0、「遇到次數」填 1。這類坑下次還會遇到，值得記。

## 怎麼寫入

一律用 log.js，內容走 heredoc：

```bash
node "${CLAUDE_PLUGIN_ROOT}/tools/log.js" --lesson global <<'EOF'
### G-002 <標題>
- 犯錯次數：1
...
EOF
```

專案教訓用 `--lesson project`。同一條教訓已存在時不要重建，也不要手改次數，用 bump：

```bash
node "${CLAUDE_PLUGIN_ROOT}/tools/log.js" --lesson-bump global G-001        # 犯錯次數 +1
node "${CLAUDE_PLUGIN_ROOT}/tools/log.js" --lesson-bump project P-003 --hit # 遇到次數 +1
```

兩者都會把「最近」改成今天。要補充情境，另外在任務檔記一行 `[紀錄]` 即可。

## 教訓格式

```markdown
### G-001 <一句話標題>
- 犯錯次數：1（agent 自己造成的次數）
- 遇到次數：0（環境或既有程式碼本來就有、agent 踩到的次數）
- 首次：YYYY-MM-DD ／ 最近：YYYY-MM-DD
- 類型：環境/工具 | 流程 | 專案慣例 | 需求理解
- 發生情境：<什麼任務、做什麼時發生>
- 根本原因：<為什麼會發生，不是「不小心」>
- 預防規則：<下次在哪個階段、做什麼、就不會發生>
- 適用時機：<什麼情況下要想起這條>
```

## 讀教訓檔（階段 0）

兩個檔案都讀，挑「適用時機」符合這次任務的條目，在探索與計畫時照做。目前全部讀；檔案長了再加關鍵字過濾。
